A step-by-step walkthrough of how we verified that the buyer portal invitation email reaches the recipient. Uses the E2E seed entity jet_pradas@yahoo.com on the test property 95 E2E Ancient Sellers Street — no production data touched.

01

Find the Test Property

The admin properties list is the entry point. We search for the E2E seed property to confirm it's in the system and visible in the admin UI before doing anything with its buyer entities.

What we searched for

Typed E2E Ancient into the general search box. The search covers street address, suburb, owner names, and buyer names — so this reliably surfaces the seed property.

1Navigate to /admin/properties
2Type E2E Ancient in the general search box and click Search
3Confirm 95 E2E Ancient Sellers Street · Playwright Seed appears in results

Properties list with 'E2E Ancient' search — 95 E2E Ancient Sellers Street visible

Why this property? It's a dedicated E2E seed property that was pre-seeded with a contact entity using jet_pradas@yahoo.com as the email address. Using seed data means we can run this verification without touching any real client records.

02

Locate the Seed Entity

Clicking the property row opens the edit dialog. Switching to the Contacts tab reveals E2E Contact 2 — the seed entity whose email is jet_pradas@yahoo.com. This is the entity we'll send the portal invitation to.

Entity details

The entity record in the database:

1entity_id: 169792 — E2E Contact 2
2email_address: jet_pradas@yahoo.com
3property_entity_id: 185950 on property 222317
4Tagged as Electrician · Buyer (association = Buyer, category = Contact)

Contacts tab — E2E Contact 2 with jet_pradas@yahoo.com visible in the admin UI

Note on entity category. The portal send-link API only needs a valid propertyEntityId — it doesn't filter by buyer category. It looks up the email directly from the entity record, so any property contact with an email address can receive a portal invitation.

03

Generate the Portal Token

Before sending the invitation, we need an active portal token for this property entity. The POST /api/admin/portal-tokens endpoint is idempotent — it returns the existing token if one already exists, or creates a new one.

How it works

The token is a UUID stored in the portal_tokens table. It's the secret that gates access to the buyer portal — the URL /portal/{token} is all the buyer needs.

1POST to /api/admin/portal-tokens with { propertyEntityId, propertyListId }
2Server checks for an existing non-revoked token for this entity
3If none exists, generates a new UUID token and inserts a row
4Returns the token record — same response whether new or existing

API call: POST /api/admin/portal-tokens — token generated (200 OK) with token UUID and portal metadata

04

Send the Invitation Email

With an active token in place, the POST /api/admin/portal-tokens/buyer/send-link endpoint composes the invitation email and delivers it via the admin's connected Gmail account.

What the API does

The endpoint reads the entity's email address from the database, builds an HTML email with the portal URL, sends it via Gmail (using the admin's OAuth token), and records the send in portal_link_sends.

1POST with { propertyEntityId: 185950 }
2Server looks up emailAddress from the entity record
3Resolves the portal URL: /portal/{token}
4Sends email via Gmail API: subject = "Your buyer portal — E2E Contact 2"
5Returns { recipientEmail: "jet_pradas@yahoo.com" }

API call: POST /api/admin/portal-tokens/buyer/send-link — email dispatched, recipient confirmed

Gmail integration. Emails are sent through the admin's connected Google account (the same one used for all admin Gmail compose actions). The sender address is the admin's Gmail, not a generic noreply — so if the buyer replies, the reply lands in the admin inbox. If Gmail is not connected, the API returns a 503 with a reconnect prompt.

05

Database Confirmation

Every send is recorded in panda_realty.portal_link_sends. This table acts as an audit log — it tracks who received each invitation, when, and which token it was tied to. The record confirmed the email reached the queue successfully.

What was recorded

The portal_link_sends row captured:

1recipient_email: jet_pradas@yahoo.com
2recipient_name: E2E Contact 2
3portal_token_id linking back to the active token
4sent_at timestamp — the exact moment the Gmail API call completed

portal_link_sends row — audit trail showing recipient, token reference, and sent_at timestamp

Resending is safe. Each click of 'Send via email' inserts a new row in portal_link_sends. The token itself is not regenerated — the same portal URL is resent. This means you can resend without invalidating the link the client already has bookmarked.

06

The Live Portal

The final confirmation: visiting the portal URL included in the invitation email. The buyer's portal loads without any login — just the unique token in the URL. This is what jet_pradas@yahoo.com sees when they click the link.

The portal shows the property summary, conditions timeline, documents, and messaging — all scoped to this buyer's deal. No account required.

Buyer portal at the invitation URL — no login required, property details loaded

Token-based access. The URL itself is the credential — there's no username or password. If the buyer loses the email, click Send via email on the portal panel to resend the same link. Revoking from the admin panel immediately kills access at that URL.
